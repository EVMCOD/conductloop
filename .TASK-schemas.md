"""The task: give every connector action an input schema.

Each connector action becomes a tool the model can call, and the model has
to know what arguments to pass. Today ``ActionSpec`` has no schema, so a tool
built from it would tell the model "call this" without saying what to call
it with.

Every action already has a handler that reads a payload. The schema has to
match what the handler actually reads — so the schema is derived from the
handler's code, not invented.

## Rules

- Add ``input_schema={...}`` to EVERY ``ActionSpec`` in the file you are
  given. A JSON Schema object: ``{"type": "object", "properties": {...},
  "required": [...]}``.
- The property names must be EXACTLY the keys the handler reads from the
  payload. Read the handler first. If the handler does
  ``payload.get("query")``, the schema has a ``query`` property.
- ``required`` lists the keys the handler cannot work without. If the
  handler has a sensible default for a key, that key is NOT required.
- The description of each property says what it means, in one line, and it
  is read by the model — write it for the model.
- A ``sync`` action that takes no arguments gets
  ``{"type": "object", "properties": {}, "required": []}``.
- Do NOT change the handler, the name, the kind or the description. Only add
  the schema.
- Keep the existing formatting and the file's style. Do not reformat
  unrelated lines.
